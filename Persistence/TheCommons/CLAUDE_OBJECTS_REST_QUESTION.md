## Facts (repo at `d2b6859`, live = the same)

- **A lookup is the whole game loop today.** Enter at a lab station -> `inventory[item] += 1` in the client, `netPickup(item)` to the daemon, a toast. No inputs consumed, no crafting
  (`pushback.md`: "real-name lookups, not a crafting economy"). Bound players' inventory is durable (cap 99 per item, `updated_at` orders "last picked"); guests' is RAM.
- **The daemon rejects any item slug not in its `items` table** (`unknown_item`). So every new item, from A or D, is a catalog row, and the live database already has its 3 rows:
  `seed.sql` only runs on an empty `items`. New rows need one idempotent startup step (an `ensure_catalog`, the same shape as `ensure_visit_policy`), which means a **daemon deploy** (backup, plan, `--go`).
  The client also bakes the catalog (`LAB_RECIPES`, the item colours in `interiors.js`); it does not fetch it.
- **Lab stations are tiles**: 3 (`T_STATION_COPPER/IRON/CHALK`) in a 20x16 room. More stations need new tile ids and new cells in `tiles.png` (generated by `art/make_art.py`; cells 36-47 are free), and the room re-laid out.
- **The schema already has a `category 'material'`** and a `placed(instance_id, item_id, x, y, rot90)` table, both unused for this. Today the ONLY thing you can place is one item in the house's wall slot ("the most recently picked up").
- **The house furniture is fixed tiles** (table, two chairs, a rug, the wall slot), the same for every house.
- **The mine has a lock: "No ore. That's honest."** (`mine-built.md`), so nothing ore-like may be added there.

## The shape I recommend for all of it

One pattern, three places: **real-name lookups, per player, never used up, nothing consumed.** It is what the lab already is, it keeps `pushback.md`'s "no economy", and it needs
no new rules (no respawn timers, no shared stock, no stealing). Items stay flat colour squares with a label (`art.md`: no item sprites).

## C. House furniture: two different sizes

- **C1. Extra fixed decor in the house room** (a shelf, a plant, a lamp, a second rug, a bookcase): baked tiles like the table and chairs, the same in every house. Client only, no migration.
- **C2. Player-placed items** (the real "objects" feature): put a lookup item you hold on the house floor, see it there, pick it back up. Uses the `placed` table that already exists.
  It is a new mechanic: a placement action (there is no inventory menu, so "place the last thing you picked up on the tile in front of you"), a cap per house, durable across restarts, visible to visitors, and an owner-only rule.
  Daemon + client + tests, its own deploy.

For C2 I would default to: floor-placeable = any item you hold; the last picked up is what you place, at the tile in front of you; a cap of 8 per house; Enter on a placed item picks it back up; owner places and removes, visitors only see.
