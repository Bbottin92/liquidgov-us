# PWA: Social, Civic and The Commons get their own home-screen apps — built, tested, NOT deployed

Brandon: `BUILD pwa` (Grok's paste: "Social and Civic get their own webmanifests ... same pattern as Mail. The Commons gets a small manifest +
apple-touch-icon on /commons/ ... Do not touch nginx unless a new file 404s. Hold for Grok before deploy."). **Nothing was deployed and the droplet
was not contacted.** `www` -> apex is deliberately not mixed in.

## What was wrong

Mail installed as Messages, but installing Social or Civic from Chrome/Android still gave "LiquidGov" and opened the Genesis landing page (they
linked the default `/manifest.webmanifest`), and `/commons/` had no manifest or touch icon at all, so "Add to Home Screen" from the plaza made a
LiquidGov bookmark. The /apps Commons tile also showed the Genesis icon.

## What changed

**Civic** (`liquidgov-platform/src/http_server.cpp`, `assets/apps.html`)
- `GET /manifest-social.webmanifest` and `GET /manifest-civic.webmanifest`, the exact shape of `/manifest-mail.webmanifest`: name/short_name, standalone,
  `background_color #f7f1e4`, the theme colours `page_wrap` already used for those titles (`#c17a4a`, `#6b7d5a`), the existing `/icon-social|civic-192|512.png`.
- `page_wrap` picks the manifest by title, as it already did for Mail: `Messages` -> mail, `Social` -> social, `Civic` -> civic, everything else -> Genesis.
  Those titles are the `/app/social` and `/app/civic` install shells that `/apps` sends people to, so the manifest is linked exactly where Add to Home Screen happens.
- **start_url is `/feed` and `/proposals`**, not the shells: Grok wrote "/app/civic or whatever those shells already redirect to", and the shells
  (`app-social.html`, `app-civic.html`) already redirect a standalone launch to exactly those two pages. Mail does the same (`start_url /mail`, the real page). The test pins each start_url to its shell's redirect target.
- The /apps Commons tile now shows the Commons icon (`/commons/apple-touch-icon.png`) and says to add it from inside the plaza.

**Commons** (`commons/`, static, no daemon, no nginx)
- `manifest.webmanifest`: "The Commons" / "Commons", `start_url` and `scope` `/commons/`, standalone, the page's own `#0c0b09` for theme and background, icons 192 and 512 "any" plus a 512 "maskable".
- `apple-touch-icon.png` (180), `icon-192.png`, `icon-512.png`, generated by **`Persistence/TheCommons/art/make_icons.py`** (stdlib only, deterministic, no Pillow here): the plaza from above on a 24x24 pixel grid, scaled with nearest-neighbour. Grass, the path crossing, the
  notice-post with its paper, a bench and a walker, all in the game's own palette. Opaque RGB (a phone rounds it; transparency would show black) and the notice-board/post sit inside the central ~66%, so the same file is safe as a maskable icon.
- `index.html` links the manifest and touch icon by absolute `/commons/...` path and adds the standalone meta tags (title "The Commons").

## Tests (in CI via `run_all.sh`; python3 only)

`tests/pwa_check.py` (**71 checks**) + `tests/test_pwa.sh`. Commons: the manifest fields, the theme matches the page, every icon exists as a real PNG of its declared size and is opaque,
the icons are byte-identical to what `make_icons.py` generates (no stale or hand-edited PNG), the icon is a real picture and maskable-safe, the links and meta tags, the client sync's `CLIENT_EXCLUDES` does not leave any of these files out, the /apps tile uses the Commons icon.
Civic, from the C++ source: the string-literal manifests are extracted and parsed as JSON, **Mail as a control** (my first extractor dropped one literal too few and the Mail control caught it before anything else did),
start_url equals each shell's redirect target, theme colour equals `page_wrap`'s, every icon is a real PNG of the right size AND in the icon route's allow-list, the picker has exactly the three app branches plus the Genesis default, and each shell renders with the title the picker keys on.
**Mutation-checked, 16 breakages**, each fails: a dropped Social/Civic branch, start_url `/`, an icon typo, a theme drift, broken JSON, a shell with another title, the Commons start_url, theme, manifest or touch-icon link removed, a hand-edited icon byte, a wrong-size touch icon,
the maskable entry dropped, the /apps tile back to the Genesis icon, and the client sync excluding `*.png` or `*.webmanifest` (my first version of that mutation used the wrong syntax and changed nothing, so it "passed"; redone against the real `CLIENT_EXCLUDES` array it fails, and renaming the array now fails too instead of passing vacuously).

## Real checks

- **Real browser, Commons** (served under a `/commons/` prefix, like nginx): the manifest link resolves (200, `application/manifest+json`), all three icon entries decode at 192/512/512, the touch icon is 180x180, the standalone meta tags are present, the console is clean and the game still loads.
- **Real compiled civic** (built locally, run against a throwaway store): the three manifests answer 200 `application/manifest+json` with the right name, start_url, theme and icons; `/app/social`, `/app/civic` and `/app/mail` each link their own manifest and touch icon; `/`, `/apps`, `/laws` and `/privacy` still link the Genesis one; all six icons serve as PNG; an unknown `/manifest-nope.webmanifest` is 404.

## Limits, said plainly

- **Not installed on a device.** I did not run Lighthouse or an Android/Chrome install; the manifests are checked for shape, links, icons and start_url, not for the browser's own installability verdict. Do one real Add to Home Screen on Android after the deploy.
- **iOS ignores manifests.** On an iPhone the home-screen icon opens the page you were on (the install shell) and uses the apple-touch-icon; the shells already redirect a standalone launch to the app page. Nothing here changes that.
- Installing from the real app pages (`/feed`, `/proposals`) still gets the Genesis manifest: only the shells carry the app manifests, as Mail's `/app/mail` does. Extending it to those titles would also change their icon/theme-colour tags, so it is left out.
- The Commons icon is my drawing; if it should look different, only `make_icons.py` changes.

## Deploy (after Grok's review; Brandon's own `deploy`)

**Client first, then civic** (this one is order-sensitive: the /apps tile loads `/commons/apple-touch-icon.png`, which only exists once the client is synced).
1. Client: `drift-check.sh --tree client` (expect `index.html` plus the four new files), `sync-client-to-droplet.sh`, verify byte-identical, and that `/commons/manifest.webmanifest` answers with a manifest content type (nginx's mime table; if it comes back as text/html or octet-stream that is the "a new file 404s / wrong type" case Grok named).
2. Civic: drift-check (the droplet's `http_server.cpp` must equal the last deployed commit), back up the binary, `sync-to-droplet.sh`, **`chown` immediately**, build `-j1`, restart only if rebuilt, read the journal for a crash loop.
3. Confirm live: the three manifests 200, `/apps` Commons tile icon 200, `/commons/` links its manifest, `/` 200, public `/internal/*` 404, `commons-daemon` untouched.
Rollback: re-sync the previous client revision and restore the `.prev-<time>` civic binary.
